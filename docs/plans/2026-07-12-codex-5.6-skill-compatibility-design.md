# Codex 5.6 Skill Compatibility Design

**Date:** 2026-07-12  
**Status:** Approved for implementation planning  
**Scope:** Active Codex-facing skills and repository model guidance

## Goal

Make the repository's active Codex guidance and skills coherent with the user's
exclusive use of the GPT-5.6 Luna, Terra, and Sol family. Preserve stable skill
tier names and verify that each model can interpret the Codex-facing workflows
without reintroducing older model assumptions.

## Model Policy

The stable repository tiers map to the current Codex models as follows:

| Repository tier | Codex model |
|-----------------|-------------|
| `fast` | GPT-5.6 Luna |
| `standard` | GPT-5.6 Terra |
| `deep` | GPT-5.6 Sol |

Model selection and reasoning effort remain separate concerns. Terms such as
`high`, `xhigh`, `max`, and `ultra` continue to describe reasoning effort or a
host-specific workflow capability; they are not renamed to model aliases.

## Compatibility Behavior

Codex named-agent definitions continue to inherit the parent session model.
They pin only the reasoning effort and read-only sandbox appropriate to their
role. This lets Luna, Terra, and Sol each host the skills without a skill
silently escalating the user's selected model or cost.

Skill workflow tiers remain unchanged. In particular, code-review intensity
names (`quick`, `standard`, `high`, and `deep`) describe review structure and
must not be conflated with the repository's model-tier examples.

## Changes

Update the three active model-guidance surfaces together:

- `README.md`
- `CATALOG.md`
- `skills.yaml`

Add a focused automated contract test that fails if:

- active Codex model guidance mentions GPT-5.4 or GPT-5.5;
- `fast`, `standard`, and `deep` do not map to Luna, Terra, and Sol; or
- the README, catalog, and manifest drift from one another.

Do not rewrite dated plans or review reports. They are historical records, and
their existing effort-tier and no-model-pin decisions remain valid.

## Model-Perspective Evaluation

After the metadata and contract test are green, run one fresh, read-only review
with each exact model slug:

- `gpt-5.6-luna`
- `gpt-5.6-terra`
- `gpt-5.6-sol`

Each reviewer receives the active Codex-facing skill packages and the approved
policy, then checks trigger clarity, instruction interpretation, tool/model
assumptions, effort semantics, and contradictions. Reviewers report findings
only; the parent evaluates evidence and makes the smallest justified fixes.

The evaluation is not a benchmark and does not require identical prose or
reasoning from all three models. Success means each model can follow the skill
contract without relying on an obsolete model, confusing a model with an
effort tier, or requiring an unavailable capability.

## Verification

The implementation is complete when all of the following pass:

1. The new model-tier contract test first fails against the old mappings, then
   passes after the metadata change.
2. `skills.yaml` parses successfully.
3. Existing sync and code-review contract tests pass.
4. Every active skill passes the installed `quick_validate.py` validator.
5. All Codex named-agent TOMLs parse successfully and remain model-unpinned.
6. Luna, Terra, and Sol compatibility reviews produce no unresolved concrete
   blocker.
7. `scripts/sync-skills --target codex --dry-run` succeeds.
8. `git diff --check` succeeds and unrelated changes remain untouched.

## Non-Goals

- Pinning named subagents to Terra or Sol.
- Changing Claude, Gemini, Cursor, or UltraCode model guidance beyond keeping
  shared tables internally consistent.
- Renaming skill workflow tiers or user-facing flags.
- Applying global skill symlinks or copying Codex agent TOMLs.
- Rewriting historical design and implementation documents.
